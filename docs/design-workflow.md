# design-workflow.md — プロっぽく仕上げる制作手順

Claude Code でサイト・LP・ブログページを「AI で作った感」なく仕上げるための手順です。
**5つの秘訣**を順に組み合わせます。単体でも効きますが、5つ揃えると差が出ます。

---

## 0. 環境の準備（初回だけ）

| 必要なもの | 補足 |
|---|---|
| Claude の有料プラン | Pro または Max。無料プランでは Claude Code は使えません |
| VS Code | 公式サイトからインストール |
| Claude Code 拡張 | VS Code の拡張機能で「Claude Code」を検索してインストール |
| 作業用フォルダ | このリポジトリ（`yamedoki-ai-money`）を VS Code で開く |

### モデルを Opus に切り替える（重要）

デフォルトは Sonnet です。**デザインの品質はモデルで大きく変わる**ので、
サイト制作のときは必ず Opus に切り替えてください。

```
/model
```

と入力し、`Switch Model` から Opus を選びます。

> Sonnet のままだと、余白が単調・配色が平凡・レイアウトがワンパターンになりがちです。
> ここを間違えると、以降の秘訣の効果が半減します。

---

## 秘訣 1：`CLAUDE.md` にルールとブランドを覚えさせる

`CLAUDE.md` は Claude Code に対する**システムプロンプト**にあたるファイルです。
Claude Code は作業を始める前に必ずこれを読むので、
ここに書いたルールは全作業に自動で反映されます。

### すでに用意済みのもの

このリポジトリの `CLAUDE.md` には、以下がルールとして入っています。

- 使う技術（React では既存のプレーン CSS、単体 LP では Tailwind CSS）
- 日本語のコメントを入れること
- レスポンシブ対応は必須
- `brand-assets/` を必ず参照すること
- スクリーンショットで自己レビューすること

### ★ 最重要：`brand-assets/` にブランドの実物を置く

**ここが仕上がりを一番左右します。**
`CLAUDE.md` に文章でルールを書くだけでなく、
**実物の画像を見せる**ことで、Claude が色・フォント・トーンを直接読み取れるようになります。

`brand-assets/` に入れるもの：

| 種類 | 例 |
|---|---|
| ロゴ | サイトロゴ、アイコン（💸 のブランドアイコン） |
| キャラクター | ブログで使うキャラクター画像があれば全ポーズ分 |
| 過去の制作物 | 過去に作った LP・バナー・アイキャッチのスクリーンショット |
| 参考にしたい配色 | 「この配色が好き」というサイトのスクリーンショット |
| フォント見本 | 使いたい書体の見本画像 |

素材が増えるほど精度が上がります。**中身が増えれば増えるほど、より高度なものができます。**

### 色・フォント・トーンは人間が決める

ここだけは AI に丸投げしないでください。

- 何色を使うか
- どの書体を使うか
- 柔らかめか、硬めか

この3つは人が決めたほうが、はるかに良いものになります。
決めた内容は `brand.md` に書いてあります。

### `CLAUDE.md` は育てるファイル

最初から完璧である必要はまったくありません。
作業しながら「これもルールにしよう」と思ったら、Claude Code にこう頼むだけです。

```
今のルールを CLAUDE.md に追記してルール化してください
```

## 秘訣 2：フロントエンドデザインスキルを使う

Claude Code の **スキル**は、特定の作業に特化したカスタム命令を読み込む仕組みです。
料理でいえばレシピ集にあたります。
Claude Code は作業のたびに「この作業に使える専用ルールがあるか」を自動で判断し、
あればそれを読み込んでから作業します。

フロントエンドのデザインスキルを入れると、次が目に見えて良くなります。

- 余白の取り方
- タイポグラフィのバランス（文字サイズのメリハリ）
- アニメーションの使い方
- 配色のコントラスト

### 導入方法

スキルは `.claude/skills/<スキル名>/SKILL.md` に置くと有効になります。
一度入れれば、**どのプロジェクトでも使えるようになります**
（ユーザー全体に入れる場合は `~/.claude/skills/` 配下）。

配布されているスキルのインストーラーがある場合は、
そのコマンドを Claude Code にそのまま貼り付けて実行すれば導入できます。

導入後、`/` メニューにスキルが並んでいれば成功です。

### 効果の確認方法

同じプロンプトで、スキルあり／なしを作り比べてください。
配色・余白・トンマナの統一感で、はっきり差が出ます。

## 秘訣 3：スクリーンショットでセルフレビューさせる

**これが一番効きます。**

Claude Code はコードを書くのは得意ですが、
通常は**ブラウザで実際どう見えているかを把握しないままコードを書いています**。
目が見えない状態で絵を描いているようなものです。

そこで **Puppeteer**（ブラウザ操作を自動化するツール）を使い、
「スクリーンショットを撮って自分で確認する」ワークフローを組み込みます。

### セットアップ

```bash
npm i -D puppeteer
```

うまくいかない場合は、Claude Code にこう頼むだけでも構いません。

```
Puppeteer をセットアップしてください
```

### 使い方

このリポジトリには `scripts/screenshot.mjs` を用意しています。

```bash
npm run dev            # 別ターミナルでローカルサーバーを起動
node scripts/screenshot.mjs http://localhost:5173
```

`screenshots/` に3サイズ分の PNG が保存されます。

- `desktop.png` … 1440×900
- `tablet.png` … 768×1024
- `mobile.png` … 390×844

### 回すループ

Claude Code に頼むときは、こう言います。

```
Puppeteer を使ってホームページの修正を行ってください
```

すると次の流れを自動で回してくれます。

1. コードを書く
2. ローカルサーバーを起動してブラウザで表示する
3. スクリーンショットを撮る
4. 撮った画像を見て「ここの余白が狭い」などに自分で気づく
5. 修正する
6. **もう一度撮って確認する**

特に効くのが **PC とタブレットの互換性**です。
「スマホでは余白が綺麗なのに PC では間延びしている」といったズレを、
撮って比べることで自分で見つけて直してくれます。

### ⚠ 注意：アニメーションには向きません

動きのある背景・トランジション・ホバー効果は、**静止画では正しく評価できません。**
Claude が「うまくいっていない」と勘違いして、正常なものを壊してしまうことがあります。

アニメーションを扱うときは、明示的にこう伝えてください。

```
スクリーンショットでの比較は不要です。コードだけ書いてください
```

## 秘訣 4：参考サイトを活用する

ゼロからデザインを考えるのは、プロのデザイナーでも大変です。
**「こんな感じにしたい」という参考を先に決めてください。**

| サイト | URL | 特徴 |
|---|---|---|
| Awwwards | https://www.awwwards.com/ | 世界のトップレベルのサイトが集まる。動きのあるサイトの参考に |
| Dribbble | https://dribbble.com/ | デザイナーの作品集。配色・UI パーツの参考に |

### 使い方

1. 上のサイトで「いいな」と思うものを **1〜3個**探す
2. そのスクリーンショットを `brand-assets/` に入れる
3. Claude Code にこう伝える

```
brand-assets/reference-01.png のような雰囲気で作ってください。
特に余白の取り方と、見出しの文字サイズのメリハリを参考にしてください。
```

**「〇〇っぽく」だけでは伝わりません。**
「どこを参考にしてほしいのか」を1文添えると、精度が大きく変わります。

## 秘訣 5：完成したら公開する

ローカルで見ているだけではもったいないので、公開まで持っていきます。
やることは3つです。

### ① GitHub にコードを上げる

1. GitHub にログインし、`New repository` からリポジトリを作る
   （リポジトリ＝ソースコードや設定ファイルを保管する場所）
2. Claude Code にこう頼む

```
このコードを GitHub にプッシュしてください
```

初回だけ GitHub の認証が必要です。認証は Claude Code と対話しながら進められます。
（プッシュ＝作成した内容を GitHub 上に保管すること）

### ② Vercel と連携する

1. [Vercel](https://vercel.com/) で `Sign Up`
2. **Continue with GitHub** を選ぶと連携が楽です
3. `Import Repository` から対象のリポジトリを選び `Import`
4. `Deploy` を押す

これで公開完了です。`Visit` を押すと公開されたサイトが見られます。

### ③ 独自ドメインを設定する

Vercel のプロジェクト設定 → `Domains` から独自ドメインを追加します。

### 以降の更新はこれだけ

一度この流れを作ってしまえば、更新は次の一言で完了します。

```
GitHub にプッシュしてください
```

Vercel が変更を自動で検知し、本番サイトを更新してくれます。
**まず Claude Code 上で表示を確認 → 問題なければプッシュ**、という順番を守ってください。

## WordPress ブログに読み替える場合

このブログは WordPress なので、秘訣 5（GitHub → Vercel）はそのまま使えません。
代わりに次のように読み替えます。

| 秘訣 | WordPress での読み替え |
|---|---|
| 1. `CLAUDE.md` | そのまま有効。ブランド定義は WordPress でも共通 |
| 2. デザインスキル | そのまま有効。追加CSS・カスタムHTMLブロックの品質が上がる |
| 3. スクリーンショット | **公開中の URL に対して実行できます**。`node scripts/screenshot.mjs https://自分のブログURL/記事URL` |
| 4. 参考サイト | そのまま有効。参考サイトのスクショを `brand-assets/` へ |
| 5. 公開 | GitHub/Vercel の代わりに、**子テーマの `style.css` をこのリポジトリで管理**し、WordPress へ反映する |

### WordPress で特に効く使い方

**既存記事の「見た目の粗さ」を洗い出す**のに、秘訣3がそのまま使えます。

```bash
node scripts/screenshot.mjs https://自分のブログURL/記事のURL
```

3サイズ分を撮って Claude Code に見せ、こう頼んでください。

```
screenshots/ の3枚を見て、スマホ・タブレット・PC で崩れている箇所と、
余白・文字サイズの問題点を洗い出してください。
修正案は WordPress の「追加CSS」に貼れる形で出してください。
```

これを**アクセスの多い記事から10本ずつ**進めるのが、一番早く「プロっぽく」なります。

## まとめ：毎回の流れ

```
1. /model で Opus に切り替える
2. 参考サイトを決めて brand-assets/ に入れる
3. CLAUDE.md と brand.md のルールに沿って作る（デザインスキルが自動で効く）
4. Puppeteer でスクリーンショット → 自己レビュー → 修正 → 再撮影
5. 問題がなくなったら公開する
```

結局のところ、**Claude に「このようにしてください」とお願いするだけ**でサイトは作れます。
その「このように」の精度を上げるのが、この5つの秘訣です。
